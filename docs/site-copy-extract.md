Carapace Core Skills Guide — Agent Builder Edition
Core Skills Guide (Agent Builder Edition)
A practical spec for AI agents to implement the 5-core-skill architecture from scratch.
0) What this guide gives you
Clear responsibilities for each skill.
Cross-skill interfaces (how skills call/reference each other).
A minimal file layout and contracts you can copy directly.
Governance + rollback requirements so adaptation stays safe.
Build sequence an AI agent can follow step-by-step.
Important:
If your agent needs help scaffolding/updating skills, use OpenClaw's built-in
skill-creator
skill for detailed packaging/structure instructions while implementing.
1) Core architecture
Do → Remember → Evaluate → Adapt → Govern → Repeat
This is a controlled improvement loop. Learning never bypasses governance.
2) The 5 skills (roles + required I/O)
Core Orchestration
Input:
objective, constraints, recalled context.
Output:
execution plan + routing decisions + result envelope.
Calls:
core-memory (read/write), tools/subagents, core-reflection-evaluation.
Core Memory
Input:
recall query OR durable memory draft.
Output:
relevant memory snippets OR persisted memory artifact.
Calls:
memory retrieval/storage only; does not make policy decisions.
Core Reflection & Evaluation
Input:
objective, constraints, execution result.
Output:
score, diagnostics, lessonCandidates[].
Calls:
core-learning (lesson candidates), optionally core-memory (log summaries).
Core Learning
Input:
lessonCandidates[] + confidence + context.
Output:
proposed behavior update(s) + expected impact + rollback key.
Calls:
core-governance for approval before durable apply.
Core Governance
Input:
proposed action/update with risk metadata.
Output:
allow / ask / deny decision + rationale.
Calls:
none required; returns policy decision to caller.
3) Cross-skill interaction map (authoritative)
orchestration.start(task)
  -> memory.recall(task)
  -> orchestration.plan(task, recalled)
  -> orchestration.execute(plan)
  -> memory.capture(result_draft)
  -> reflection.evaluate(task, result)
      -> learning.propose(lessonCandidates)
          -> governance.decide(updateProposal)
          -> if allow: learning.apply(updateProposal)
          -> if ask: queue for human approval
          -> if deny: archive proposal (no apply)
  -> memory.capture(final_decisions)
  -> orchestration.return(final_response)
4) Minimal file layout (starter)
skills/
  core-orchestration/
  core-memory/
  core-reflection-evaluation/
  core-learning/
  core-governance/
memory/
MEMORY.md
ops/
  updates-log.jsonl
  rollback-map.json
  approvals-queue.json
5) Required contracts (copy this spec)
{
  "taskContract": {"objective":"string","constraints":["string"],"doneDefinition":"string"},
  "resultEnvelope": {"status":"ok|partial|failed","artifacts":["string"],"notes":"string"},
  "evaluationRecord": {"score":0.0,"diagnostics":["string"],"lessonCandidates":[{"text":"string","confidence":0.0}]},
  "learningProposal": {"updateId":"string","scope":"prompt|workflow|tooling|memory-policy","change":"string","expectedImpact":"string","rollbackKey":"string"},
  "governanceDecision": {"decision":"allow|ask|deny","reason":"string"}
}
6) Build workflow for an AI agent
Create folder skeleton + SKILL.md for all five skills.
Implement contracts first.
Wire orchestration→memory recall before execution.
Wire post-execution reflection and lesson emission.
Wire learning proposals through governance gate.
Add apply + rollback paths for approved updates only.
Add memory writes for decisions and outcomes.
Run 10-task test suite and compare pre/post scores.
7) Governance policy baseline
Auto-Allow
Read-only local analysis.
Formatting/summarization.
Low-risk internal planning.
Ask First
External messaging/posting.
Payment or wallet operations.
Durable behavior/policy changes.
Deny by default
Destructive actions without explicit approval, and any attempt to bypass governance for learning updates.
8) Testing protocol (must pass)
Recall test:
skill can retrieve relevant prior decisions.
Evaluation test:
every non-trivial task emits evaluationRecord.
Learning gate test:
unapproved update cannot be applied.
Rollback test:
applied update can be reverted by rollbackKey.
Safety test:
high-risk actions return ask/deny as expected.
9) OpenClaw implementation note
When your building agent needs deeper help creating or updating skill packages, invoke OpenClaw's
skill-creator
skill for SKILL.md structure, packaging conventions, and repeatable scaffolding.

## Pitch Deck (ideas/index.html)

### Slide 1: Own Your Intelligence

**Image:** `1.png`

Every company is being told they need AI, but most AI products ask you to surrender something important: your data, your workflows, your internal knowledge, or your strategic control. Our view is different. We believe your intelligence layer should belong to you.

Carapace installs and manages a private AI operating layer for your organization. That means you can use the capabilities of frontier AI, local models, agents, and automation without being locked into one vendor or handing over the core of your business.

The important distinction is that we are model independent. We are not telling you, “Use this one model forever.” We are building the harness that lets you use the right model for the right job. Sometimes that may be GPT, Claude, Gemini, Qwen, or another frontier model. Sometimes it may be a local model running in your environment. Sometimes it may be a specialized tool or automation.

The point is control. Your business sits at the center. Carapace becomes the intelligence layer between your business and the AI ecosystem, so you can take advantage of the best available technology without giving up ownership of your data, workflows, or strategy.

---

### Slide 2: Your Employees Are Acting as APIs

**Image:** `3.png`

Inside most companies, the problem is not that people are lazy or incapable. The problem is that very capable people spend too much time acting as human middleware.

They copy information from one system to another. They search for files. They move things between email, spreadsheets, CRMs, folders, PDFs, Slack, Notion, accounting systems, and project tools. They chase approvals. They reformat documents. They re-enter information that already exists somewhere else.

In other words, the employee becomes the API.

That creates hidden costs: lost time, manual errors, slower execution, and frustration. People did not join the company to be human plumbing.

This is where Carapace comes in. We become the intelligence layer between people, software, and AI.

We connect tools, automate the busywork, unify information, and give people back time to focus on judgment, creativity, clients, strategy, and outcomes.

We are not replacing your team. We are removing the low-value connective tissue work that is currently draining them.

---

### Slide 3: What Work Shouldn’t Exist Anymore?

**Image:** `4.png`

The best automations are usually not futuristic. They are often the most boring, recurring, annoying tasks in the company — the work everyone already knows is wasteful, but no one has had the time, tools, or structure to eliminate.

So when we come into a business, one of the first questions we ask is: what work should not exist anymore?

That usually means repetitive work: copying data, weekly status updates, manual entry, and repetitive document handling.

It also means fragile work: things that depend on one person, tribal knowledge, undocumented processes, or “only Sarah knows how to do that” workflows.

There is hidden work: searching for files, digging through old proposals, hunting through email threads, or trying to find information that technically exists but is not accessible at the moment of need.

There is coordination work: approval chains, handoffs, status chasing, and work about work.

And then there is rework: formatting, corrections, rebuilding the same thing, rewriting the same email, or recreating the same report.

The goal is not to automate everything. The goal is to identify the work that drains time, creates risk, and blocks momentum.

Cortex eliminates low-value work so the team can focus on what moves the business forward.

---

### Slide 4: You Don’t Need an AI Department

**Image:** `6.png`

Most businesses know AI matters, but they do not have the time or internal expertise to track every model release, understand hardware requirements, compare benchmarks, evaluate privacy risks, build local infrastructure, manage API routing, configure agents, and maintain governance.

That is what we do.

We become your private AI infrastructure team.

That can include helping you select and right-size hardware. It can include local, private cloud, hybrid, or cloud deployment. It can include secure installation, configuration, integrations, data access, policies, approvals, audit logs, and continuous improvement.

You do not need to become an AI lab. You need the benefits of one.

This is where our experience becomes valuable. We are already testing models, evaluating tools, watching the frontier, comparing local options, and learning what actually works in practice. We take that moving landscape and translate it into a practical, governed stack for each client.

What the client gets is no vendor lock-in, less guesswork, fewer surprises, better visibility, and proactive support.

We handle the complexity. The client gets the competitive advantage.

---

### Slide 5: Your AI Should Never See Your Secrets

**Image:** `2.png`

For most companies, the hesitation is not intelligence itself. It is exposure. Passwords, API keys, client records, financial data, private files, personal information, and business strategy all become dangerous if they are casually pushed into a model context.

Cortex is designed around a simple idea: the model should only receive what it actually needs. Passwords, tokens, credentials, and sensitive information are isolated and masked until the exact moment they are required for execution. The model does not need to “know” the secret in order for the workflow to work.

That gives us a very clear principle: the model cannot leak what it never received.

This matters because we are not asking the client to trust a black box. The system is designed to be inspectable. You can verify the data path, audit what was accessed, and see how information moved through the workflow.

Because Cortex is model independent, the client is not trapped. If one provider changes its policies, pricing, availability, or suitability, the organization can route elsewhere. Local models, private cloud models, and frontier APIs can all be part of the same governed environment.

The message is simple: AI capability without surrendering data ownership, operational control, or provider choice.

---

### Slide 6: Trust Should Be Inspectable

**Image:** `9.png`

Every AI vendor claims security, governance, and control. The question is: can the company verify those claims?

Cortex is designed so trust is not just a promise. It is a feature.

The system is organized around inspectable layers: policies, approvals, routing, models, and audit logs.

Policies define the company’s rules and boundaries. Approvals keep humans involved where judgment matters. Routing shows why a request went to a specific model, provider, tool, or environment. The model layer remains agnostic, so work can be local, private, or frontier-based depending on need. Audit logs make the process visible after the fact.

That matters because companies do not just need AI that works. They need AI they can explain, govern, and improve.

Open governance also makes the platform more resilient. If models change, vendors shift, pricing changes, or regulations evolve, the company is not trapped. The workflow can adapt because the control layer belongs to the company.

Community tested. Company controlled.

Transparency is not something we ask clients to believe in. It is something we build into the way the system works.

---

### Slide 7: Control the Destination. Not the Vendor.

**Image:** `5.png`

Cortex is the control plane for AI work. Every request comes in, and Cortex decides where that request should go based on the company’s policies, security rules, cost preferences, speed requirements, context needs, and approval requirements.

That is very different from simply buying one AI product and hoping it fits every use case.

Some work should stay local. Some work can safely go to a frontier model. Some work may belong in a private cloud environment. Some work should go to a specialized tool. Some work should require approval before anything happens.

Cortex gives the company a way to define those rules.

You decide where data lives. You decide who can access what. You decide what needs approval. You decide how work gets routed. You decide what gets logged.

Then Cortex enforces those decisions.

The key sovereignty point is this: the company should control the destination, not the vendor. You should not have to reorganize your business around one AI company’s product roadmap, pricing, policy changes, outages, or limitations.

Cortex gives you the power to use any model or provider without giving up control of your data, workflows, or strategic direction.

### Slide 8: Finding the Right Model for the Right Job

**Image:** `7.png`

Every request is different.

A summarization task may not need the same model as a legal-style comparison. Extracting dates and amounts from documents is different from drafting a proposal. Fast classification is different from nuanced writing. Some work should prioritize cost. Some should prioritize quality. Some should prioritize privacy. Some should prioritize latency.

Cortex handles that routing problem.

Instead of asking employees to know which AI model to use, Cortex can map requests to capability aliases: summarize, extract data, classify, compare, draft, and so on. Behind those aliases, Carapace maintains and evaluates the model roster.

That roster can include frontier models, local models, private cloud models, open-weight models, specialized models, and future models that are not even on the market yet.

The value is not just access to models. The value is stewardship.

We test, benchmark, monitor, recommend, and update the options. Then Cortex routes work based on capability, cost, speed, context, policy, and outcome.

So instead of the client constantly asking, “Which model should we use now?” they can focus on the work.

Best outcome, automatically: right capability, right cost, right speed, right for the business.

### Slide 9: Small Wins First. Scale Later.

**Image:** `8.png`

A lot of AI initiatives fail because they start too big. They try to transform the whole company before anyone has seen practical value. That creates confusion, resistance, cost, and risk.

Our approach is the opposite: start small, prove value, then expand with confidence.

First, we discover. We look for repetitive work, information bottlenecks, SaaS overlap, security requirements, and strong automation candidates. This is where we find the leaks.

Second, we deploy. We create a private Cortex environment — local, cloud, or hybrid — with security controls, governance policies, model roster, and the right knowledge connections.

Third, we launch the first wins. These are usually one or two real workflows, not theoretical demos. It could be internal knowledge retrieval, proposal generation, approval routing, reporting automation, document processing, or another high-value workflow.

Fourth, we measure. We track hours saved, vendor costs reduced, process improvements, user adoption, and operational impact.

Fifth, we expand. Once there is evidence, then we scale into more departments, more workflows, more operators, and more integrations.

This makes adoption safer and more believable. We are not asking the client to buy a giant transformation project on faith. We are proving value on real work and growing from there.

Cortex Feature List
The private AI control plane for real business work
Cortex gives your business a governed AI workspace: one place to route requests, control models, manage
context, supervise agents, approve actions, and turn scattered work into repeatable systems.
1. Proprietary Context Management
Cortex is built to control what the model sees, when it sees it, and how much context is actually worth
spending.
Instead of dumping entire files, transcripts, histories, and tool outputs into every prompt, Cortex uses
structured context handling, summaries, cached reads, tool-output shaping, session memory, and retrieval
surfaces to keep AI work focused.
Why it matters: lower token waste, lower cost, faster runs, cleaner prompts, and less unnecessary
exposure of sensitive information.
2. Intent-Aware Routing
Cortex does not treat every request the same.
An intent layer evaluates what the user is actually trying to do — summarize, extract, classify, compare,
draft, search, route, automate, approve, or execute — and then chooses the right path.
That path may use a local model, a frontier model, a private cloud model, a tool, a workflow, a human
approval gate, or a delegated agent.
Why it matters: better outcomes without asking employees to understand model selection, token budgets,
tool routing, or infrastructure tradeoffs.
3. Model-Independent Execution
Cortex is not tied to one AI provider.
It can work across local models, open-weight models, private deployments, and frontier APIs. The business
keeps the control layer even as models, prices, policies, and providers change.
Why it matters: no single-vendor dependency, better cost control, and the flexibility to use the right model
for the right job.
1

4. Human-in-the-Loop Governance
Cortex is designed for supervised automation.
Approvals, audit logs, transcripts, budgets, routing rules, and execution boundaries make it clear what
happened, what was approved, and where work went.
Why it matters: AI can move faster without removing human judgment from sensitive or high-value
decisions.
5. Custody-First Security
Cortex keeps business control at the center.
Credentials, files, prompts, workflows, browser sessions, routing rules, and execution paths can remain
under the client’s environment and governance model. Sensitive information is handled through controlled
access patterns instead of casual prompt exposure.
Why it matters: the model cannot leak what it never received.
6. Fling: Capture Work From Anywhere
Fling is Cortex’s proprietary capture-and-routing layer.
An operator can grab useful context from a webpage, feed card, document, browser session, or selected
content and send it to the right destination: intake, chat, job queue, webhook, feed, agent, or workflow.
Why it matters: useful work does not stay trapped in browser tabs, screenshots, links, email threads, and
manual copy-paste.
7. Signal-to-Work Intake
Cortex can turn external signals into actionable work.
Browser captures, pasted text, links, social traffic, email, feed items, documents, and media can pass
through trust checks, routing rules, approval gates, and landing queues before becoming tasks or
automations.
Why it matters: Cortex does not just answer questions. It receives operational signal and helps route it into
useful work.
8. Ranked Feeds and Work Queues
Cortex includes feed and queue surfaces that help operators review, prioritize, and act on incoming items.

Feeds can combine daily briefs, captured content, intake candidates, media, social items, and work-ready
signals into a governed review flow.
Why it matters: teams get an operating inbox for AI-assisted work instead of another pile of disconnected
notifications.
9. Multi-Tool Agent Workspace
Cortex supports serious tool-using agents.
Agents can use first-party tools, run scripts, search workspaces, read and send email, operate through APIs,
enqueue jobs, and execute structured workflows under supervision.
Why it matters: Cortex moves beyond chat into governed execution.
10. Workflow Orchestration
Cortex can break complex work into phases: route, plan, execute, critique, archive, and improve.
Different models or tools can be used for different phases, with approvals and checkpoints where needed.
Why it matters: complex business work becomes repeatable instead of dependent on one person
manually coordinating everything.
11. Local + Remote Deployment Flexibility
Cortex can operate locally, remotely, or in hybrid patterns depending on the client’s security, cost,
performance, and integration needs.
Why it matters: businesses can adopt AI without reorganizing their entire workflow around a hosted black
box.
12. Workspace and Filemap Awareness
Cortex can help organize and reason across business files, project structures, documents, and working
context.
Instead of forcing users to manually locate and paste everything, Cortex can build a more usable map of the
work environment.
Why it matters: hidden knowledge becomes available at the moment of need.

13. Email, Browser, Social, and Media Integrations
Cortex is built to connect with the places work already happens: email, browser sessions, social channels,
files, feeds, media workflows, job queues, and scriptable APIs.
Why it matters: automation fits the business instead of forcing the business into one app.
14. Team Sessions and Delegated Workers
Cortex can coordinate multiple controlled work sessions or delegated workers, each with its own task,
boundary, and trust level.
Why it matters: larger tasks can be split across agents without losing oversight.
15. Script SDK, API, and MCP Surface
Cortex exposes developer-facing surfaces for scripts, extensions, tools, and host applications.

Why it matters: the platform can grow with the client instead of staying trapped as a single chat window.

Cortex is built around inspectable work: transcripts, logs, routing decisions, approvals, feedback, and
